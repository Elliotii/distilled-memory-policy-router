v1.1 / v1.2 Roadmap

以下是后续扩展设想，不是 v1.0 已完成内容。v1.0 只关闭了 saved-prediction replay、benchmark packaging、micro-pilot artifacts 和中文作品集包装。

v1.1：恢复 live LoRA 推理

Adapter artifact

从 AutoDL / artifact tarball 中保存并校验 LoRA adapter，记录 hash、config 和 base model 依赖。

WSL 环境

后续下载到 WSL，本地建立隔离环境，避免把 base model 或 adapter 权重提交进 git。

Live router CLI

实现一个最小 CLI：输入 candidate memories 和 current units，输出 READ / STORE / SKIP + target。

v1.1：简单 memory-agent demo

目标不是做端到端产品，而是展示 router 在一个受控 harness 里的位置。

user input
  -> current unit extraction
  -> candidate memory provider
  -> live router
  -> selected memory context
  -> downstream answerer
  -> STORE preview + audit trace

Web UI 设想

界面区域 展示内容
用户输入 当前任务或对话片段。
current units 从当前输入中拆出的待路由单元。
candidate memories 候选记忆列表，带 memory ID 和 target/type。
router input / output 展示结构化输入，以及 READ / STORE / SKIP + target 输出。
selected memory context READ 后会注入给下游模型的记忆上下文。
downstream LLM response 固定 prompt 下的回答，带 citation / grounding 检查。
STORE preview 只预览待写入内容，不直接写入长期记忆。
audit trace 记录路由输入、输出、引用、跳过原因和人工复核字段。

技术选型

服务层

FastAPI 用于 router service 和 artifact API；Streamlit 可作为最快速 demo 方案。

前端

React 适合做更完整的 audit UI；v1.1 可先用轻量页面或 Streamlit。

Memory store

SQLite 或 JSON memory store 作为可审计 stub，不追求复杂数据库能力。

Retriever stub

BM25 / keyword retriever stub 只用于生成候选集，仍需明确它不是 v1.0 评测对象。

WSL LoRA service

单独进程加载 adapter，CLI / Web UI 通过本地接口调用，便于隔离模型依赖。

明确边界

以上都是 v1.1/v1.2 计划，不是 v1.0 已完成内容。v1.0 不包含 live LoRA 推理、不包含 Web memory agent、不包含真实 memory lifecycle，也不包含线上部署结论。

建议下一步从 live router CLI 开始，而不是直接做复杂 UI。
