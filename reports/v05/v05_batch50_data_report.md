## 13. Representative Examples

### Example 1: v05_batch50_0006 (STORE/SKIP-only, service vs task vs repo)

Pipeline quality check: u1 defines a durable 10% row-count deviation rule → service_memory. u2 is the current implementation plan → task_state. u3 describes where metrics data lives → repo_memory. Three distinct targets in one case.

### Example 2: v05_batch50_0014 (READ+STORE joint, user_profile memory, sensitive SKIP)

Notification priority: Reads m2 (user silent-hours preference) because it interacts with u1's CRITICAL bypass rule. u1 stored as service_memory. u2 (home address) SKIPped as sensitive. u3 (API doc update) stored as repo_memory.

### Example 3: v05_batch50_0024 (STORE/SKIP-only, dual project_memory)

Two cross-service rules: u1 (never log PII) → project_memory (applies across ALL services). u2 (centralized secret manager) → project_memory (project infrastructure policy). u3 (current PII masking task) → task_state.

## 14. Known Limitations

- **50 cases is still not a training dataset.** This is batch validation. Target is 500-1000 for actual training.
- **Cases are agent-generated.** Semantic labels may contain biases that a human annotator would catch.
- **Domain variety:** Three project domains (memory-router, mobile-field, data-platform) recur. Real training data needs broader variety.
- **No multi-turn context:** All cases are single-turn. Multi-turn is out of scope for now.
- **user_profile at minimum:** Only 4 user_profile STORE units across 50 cases. Scaling should increase this.
- **Sensitive placeholders:** All sensitive values use obvious synthetic values (555-XXXX, testpass_..., ABCD-1234, sk_test_..., etc.). Real training must use equally obvious placeholders.
- **Not locked gold.** These labels may change after further review.

## 15. Why This Is Not Final train/dev/gold

- 50 cases total — 10-20x too small for training
- No dev/gold split — all 50 are in one file as "batch"
- Not locked — labels may change after semantic audit
- No distribution balancing for specific training objectives
- Agent-generated, not domain-expert-annotated
- Source = `v05_batch50_dry_run`, not `v05_train`/`v05_dev`/`v05_gold`

## 16. Recommendation

**Proceed to full semantic audit** of the 50-case batch (see companion report `v05_batch50_semantic_audit.md`), then make a scale decision (see `v05_batch50_scale_decision.md`).

If the semantic audit finds no blocking issues, the batch50 set can serve as a template for scaling to 100+ cases. If issues are found, apply corrections before scaling.
